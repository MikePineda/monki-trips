# monki-trips — implementation plan (MVP: phases 0–4) + cloud-ready repo

Approved 2026-11-07. Product brief: [`../BRIEF.md`](../BRIEF.md). Items marked `[verify]` were not confirmed when the plan was written; resolve them in the stated phase and log the outcome in `docs/LESSONS.md`.

## 1. Context and decisions

A travel app to plan, travel and keep the history; for two people today and open to the public later without a rewrite. Above all it must let people follow the itinerary to the letter and keep the whole trip in one place **without internet**. First real case: an 18-day multi-country trip with several time zones and currencies, starting late January 2027; the app must be loaded and usable offline by **15 January 2027**. Production runs on the production host (a Docker Swarm deployment behind a CDN).

Second goal: **the repo is worked from Claude Code cloud sessions** (Anthropic-hosted) without losing quality. It is born cloud-ready: SessionStart hook, self-contained suite, fakes for every external provider, network guard in tests, GitHub Actions as the x64 and ARM test bench. Lessons are distilled into the owner's project-starter skill so future projects are cloud-ready too.

**Decisions from the brief**

- Code, commits, README and comments in English; UI en/es with i18n from day one. Open source.
- Offline-first outweighs AI: if something must be cut before the trip, cut AI, never offline.
- Multi-user from day one; shared trips with `owner`/`editor`; more than two people per trip.
- AI behind an Anthropic-Messages-compatible adapter (MiniMax first); tools propose, the user confirms. No business logic tied to a provider.
- Mascot with states (happy, worried, excited, asleep, celebrating, thinking); replaceable sprites; passport stamps; first deliverable `/styleguide`.
- PWA; Capacitor only if iOS limits get in the way. In-app map is phase 4; the MVP has "Directions".

**Decisions taken in planning (2026-11-07)**

- **Name and domain:** `monki-trips`, repo <https://github.com/MikePineda/monki-trips>. The production domain sits under an existing wildcard certificate (no cost). Docs use `trips.example.com`.
- **Public repo from the first commit** for free GitHub Actions (x64 and ARM runners, rulesets). The owner creates the repo and makes the first push (agents never create public surfaces). AGPL-3.0-only, copyright "monki-trips contributors".
- **Laptop vs cloud:** the laptop does only the base (minimal cloud-ready scaffold, `verify:quick`, host infra that needs ssh or the host API, skill update). Design-in-code, API, web and features run in cloud sessions.
- **Split budget:** schema from migration 1 (`expense_shares`, who paid); UI and balances in phase 4.
- **Users/roles from day one:** full auth cycle (signup gated by `REGISTRATION_OPEN`, e-mail verification, reset, invitations, roles) with the schema ready although registration starts closed. No platform role for now (see backend).
- **Default UI language:** English, following the device language (Spanish when the device prefers it). Error messages follow the same rule.
- **Working mode:** the planning session is the _master agent_; it delegates as much as possible to Opus subagents (`general-purpose`, `model: "opus"`, never `fork`).
- **Friction log → skill:** versioned `docs/LESSONS.md` (English, no names) where every session and subagent notes what did not work; at the end of each phase the master distils the general lessons into the owner's personal project-starter skill (laptop only).
- **Two mandatory design gates:** no feature UI until the owner has seen it. **Gate 1 (end of WP 0.4):** 3 directions (Today in light and dark, palette, typography) and 3 mascots with their 6 states, as 390×844 PNGs in a `design: round 1` PR + an HTML page to view from the phone; the owner picks a direction and a mascot (or asks for round 2). **Gate 2 (end of WP 0.7):** `/styleguide` deployed to production (tokens, typography, components, mascot, stamps, en/es, light/dark) + PNGs of key screens; owner approves → label `design-approved`. WP 0.6 (web foundation) and 1.x use placeholder tokens and **build no product screens** before gate 2; only shell, auth and plumbing.
- **Third-party `interface-design` skill:** not installed. It duplicates `web-design-guidelines` + anti-vibe rules + `DESIGN.md`; only the idea of a `design-review` checklist inside the repo skill is kept.
- **Stack:** AdonisJS **7** (the brief said 6; the reference app uses 7) + Angular 22 + Postgres 17 + Node 24.22.2, same shape as the reference app (a sibling project of the owner).
- **Privacy (infra):** the production domain contains personal names → **it never enters the repo**. Code uses `APP_URL`; docs use `example.com`. The real URL lives only in the host, the CDN, the private ops file and the cloud environment variable `SMOKE_BASE_URL`. The backup destination name never enters the repo either.

## 3. Working mode: master agent + Opus subagents

- The **master** (planning session, and any cloud session that takes over) decides, slices WPs, writes briefs, launches subagents, integrates, runs the gate, opens PRs via REST, talks to the owner, keeps `docs/QA.md`, `docs/BACKLOG.md`, `docs/LESSONS.md`. It writes no code beyond one-line integration fixes.
- **Subagent** = one WP: `Agent` with `subagent_type: "general-purpose"`, `model: "opus"`, `isolation: "worktree"` when parallel. Never `fork`. Six-part brief: goal + done, read-first, contract copied from this plan, rules, mandatory verification, report ≤ 25 lines. Every brief also says: **"anything in the plan or the environment that did not work as written goes to `docs/LESSONS.md` as a dated line"** and **"never print `$PRIVACY_PATTERNS`, never write names, e-mails, cities, booking codes or the production domain"**.
- The master reads reports, not diffs. Risky packages (auth, tenancy, sync, storage, secrets) pass a **read-only Opus reviewer** before merge. If a subagent fails twice, rewrite the brief, not the code.
- **Cloud limits (4 vCPU):** at most 2 implementing subagents in parallel; one full `npm run verify` at a time (others `verify:quick`); for more parallelism the owner opens separate cloud sessions, one branch each. No Projects or multi-repo (repo hooks do not run there). State lives in git: `docs/BACKLOG.md` is updated and pushed after each WP; after a reclaim the master rereads BACKLOG, `git log` and open PRs via REST.
- **PRs via REST (master only):** set `REPO_URL=https://github.com/MikePineda/monki-trips; R="repos/${REPO_URL#https://github.com/}"`, then create `gh api "$R/pulls" -f title -f head -f base=main -f body`; checks `gh api "$R/commits/<sha>/check-runs"`; merge `gh api -X PUT "$R/pulls/<n>/merge" -f merge_method=rebase`. `$R` has the same meaning everywhere below. Branches delete themselves (`delete_branch_on_merge`). Subagents: Conventional commit + push of their branch, then stop; never `gh`.
- **Autonomy (decided by the owner):** push branches and open PRs without asking; **autonomous merge** (rebase) when the gate, the 7 required CI checks and, for risky packages, the Opus reviewer are green. Merge to `main` = deploy. The owner approves only product, the two design gates and the "owner only" steps. Barriers: pre-push with patterns + `check-commits`, required CI, ruleset without bypass.

| Money           | `bigint` minor units, `*Minor` names (some currencies have 0 or 3 decimals). | Sync cursor     | Trigger `sync_stamp()` on every syncable table: `change_xid xid8 = pg_current_xact_id()`, `change_seq = nextval('sync_change_seq')`, `updated_at`. Pull returns `(change_xid, change_seq) > cursor` **and** `change_xid < pg_snapshot_xmin(pg_current_snapshot())` (never skips concurrent transactions). **Sync contract** (wins over the frontend proposal of `snapshot?since`):

- **Pull** `GET /sync/pull?cursor=&limit≤500`, all the user's trips → `{ data: { changes: [{ entity, row }], tripIds, cursor, hasMore } }`. No cursor = full snapshot without tombstones. Cursor older than the purge horizon → 410; the client clears its cache, keeps the outbox and refetches everything. `tripIds` is authoritative: the client purges trips not listed.
- **Push** `POST /sync/push { mutations: [{ mutationId, tripId, entity, op: upsert|delete, id, changes, changedAt }] }` (≤ 100). Entities: trip, traveller, stop, event, segment, seat, document (metadata), task, budget_category, expense, expense_share, emergency. Each mutation in its own transaction: VineJS per entity, membership (else `rejected E_ROW_NOT_FOUND`), role, LWW merge, derived values, `trip_activity`, `print_tasks`. Response `{ results: [{ mutationId, status: applied|partial|duplicate|rejected, rejectedFields?, error?, row }] }`; a repeated `mutationId` returns the stored response; an existing `id` in another trip → 404.

**`scripts/cloud-setup.sh`** (hook; cloud only; always `exit 0`)

```bash
#!/usr/bin/env bash
# SessionStart hook (startup|resume). Cloud only; never fails the session: always exits 0.
[ "${CLAUDE_CODE_REMOTE:-}" = "true" ] || exit 0
cd "${CLAUDE_PROJECT_DIR:-$(dirname "$0")/..}" || exit 0
LOG=.claude/cloud-setup.log; mkdir -p .claude; : >"$LOG"; STATUS=()
note() { STATUS+=("$1"); echo "cloud-setup: $1" >>"$LOG"; }
envx() { export "$1"; [ -n "${CLAUDE_ENV_FILE:-}" ] && echo "export $1" >>"$CLAUDE_ENV_FILE"; }
# 1. Node 24 from /opt/node24 (environment setup script), browser and E2E settings.
[ -x /opt/node24/bin/node ] && envx "PATH=/opt/node24/bin:$PATH"
want="$(cut -d. -f1 .nvmrc)"; have="$(node -p 'process.versions.node.split(".")[0]' 2>/dev/null)"
[ "$have" = "$want" ] && note "node $(node -v), npm $(npm -v)" || note "WARN node major '$have', expected $want: re-run the environment setup script"
envx "PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1"; envx "CHROME_PATH=${CHROME_PATH:-/usr/bin/google-chrome}"; envx "E2E_WORKERS=${E2E_WORKERS:-2}"
# 2. Dependencies: only when an input of `npm ci` changed (same install as CI).
stamp=node_modules/.cloud-setup.sha256
mapfile -t inputs < <(printf '%s\n' scripts/cloud-setup.sh .nvmrc package-lock.json; git ls-files '*package.json' .npmrc)
if sha256sum --check --status "$stamp" 2>/dev/null; then note "deps: up to date"
else rm -f "$stamp"
  if timeout 420 npm ci --ignore-scripts --no-audit --no-fund >>"$LOG" 2>&1 && npm rebuild --strict-allow-scripts >>"$LOG" 2>&1; then
    sha256sum "${inputs[@]}" >"$stamp" 2>>"$LOG"; node scripts/install-git-hooks.mjs >>"$LOG" 2>&1; note "deps: installed"
  else note "WARN deps: npm ci failed, see $LOG"; fi
fi
node scripts/ci/check-lockfile.mjs >>"$LOG" 2>&1 || note "WARN lockfile guard failed, see $LOG"
# 3. apps/api/.env for a fresh clone (tests load .env.test on top of it).
if [ ! -f apps/api/.env ] && [ -d node_modules ]; then
  cp apps/api/.env.example apps/api/.env && (cd apps/api && node ace generate:key) >>"$LOG" 2>&1 && note ".env: created"; fi
# 4. Postgres for Japa: Docker (postgres:17) first, system Postgres 16 as fallback.
if ! docker info >/dev/null 2>&1; then (setsid dockerd >/tmp/dockerd.log 2>&1 &)
  for _ in $(seq 30); do docker info >/dev/null 2>&1 && break; sleep 1; done; fi
if timeout 120 docker compose -f compose.dev.yaml up -d --wait db >>"$LOG" 2>&1; then note "db: docker postgres:17 on 127.0.0.1:5432"
elif service postgresql start >>"$LOG" 2>&1 && su postgres -c "psql -q -f $PWD/docker/postgres/fallback.sql" >>"$LOG" 2>&1; then
  note "WARN db: docker unavailable, system Postgres 16 on 5432 (CI on 17 is the authority)"
else note "WARN db: no Postgres; functional tests will fail (see $LOG)"; fi
printf '%s\n' "${STATUS[@]}"   # SessionStart stdout becomes session context
exit 0
```
